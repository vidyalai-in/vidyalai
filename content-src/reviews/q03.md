## Issues found
- Late Chunking link pointed to https://arxiv.org/abs/2409.04669, which is "Learning Optimal Stable Matches in Decentralized Markets with Unknown Preferences". Correct paper is https://arxiv.org/abs/2409.04701 (Guenther, Mohr et al., 2024).
- "LegalBench-RAG evaluates precision and recall at the character-span level" / "compares chunking strategies": the paper's ground truth is (file, character-span) tuples scored with Precision@k and Recall@k; its chunking comparison is only naive fixed-size (500 characters) vs Recursive Character Text Splitter. Wording tightened. Added its finding that Cohere rerank-english-v3.0 underperformed no reranker on legal text, which supports the post's "legal-domain or fine-tuned reranker" advice.
- CUAD stats verified (510 contracts, 13,000+ labels, 41 clause types) via the Atticus Project page and arXiv abstract.
- Contextual-retrieval cost "~$1/M tokens": Anthropic's $1.02/M assumes Claude 3 Haiku 2024 pricing, 8k-token docs and 800-token chunks. Because every chunk call re-reads the cached doc, cost per token scales with doc length / chunk size; re-running the arithmetic (Haiku 3: $0.25 in, $0.30 cache write, $0.03 cache read, $1.25 out per MTok, which reproduces ~$0.99/M for Anthropic's setup) for 30k-token contracts with 300-token chunks gives ~$4/M. Claude 3 Haiku no longer appears on Anthropic's current pricing page, so the post says to re-price.
- "Typical result: 50-300 chunks per contract": consistent only for mid-to-large contracts. Replaced with a worked example (40 pages ~ 20k tokens / ~300 per chunk ~ 65; 300 pages ~ 500).
- "In my experience, structure-aware chunking with context beats fixed windows by a wide margin": unverifiable first-person anecdote. Rephrased as an expectation to be tested, noting public evidence is limited.
- LIBOR ceased publication in 2023; kept as an exact-string example but marked "in legacy contracts".
- Escapes: `Q\&A`, `\[...\]`, `\>`, `superseded\_by`, `\<100`.

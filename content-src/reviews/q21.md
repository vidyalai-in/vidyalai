## Issues found
- "About $0.03 per 1K output tokens all-in" is wrong. $27k/day ÷ (300k tok/s × 86,400 s = 25.9B tokens/day) = $0.0010 per 1K at peak-all-day; at a 1/3-of-peak daily average (8.6B tokens/day) = $0.0031 per 1K. The original was 10-30x too high.
- Dated examples for October 2026: "Llama-3.1-70B" as the dense example, "Mixtral" as an MoE example, H100 as the only reference GPU, no FP4.
- Fleet sizing summed 60 decode + 35 prefill replicas to "80-90" without saying why it is less than 95 (overlap via chunked prefill).
- 4K prompt prefill: 4,096 × 140 GFLOP ÷ 3.2 PFLOPS = 179 ms, so "about 170 ms" rounded slightly low; now "about 180 ms".
- H100 "800 TFLOPS at 40% MFU" is correct only against the dense FP8 peak (1,979 TFLOPS); NVIDIA's headline 3,958 is with sparsity. Made explicit.
- Tradeoffs table had a fake header row with literal bold markers and `\~` escapes; horizontal rule separators.
- Interview voice: "I'd use", "my default", "Pitfalls interviewers probe".

## Changes made
- Recomputed cost per token with explicit arithmetic: $0.001-0.003 per 1K output tokens ($1-3 per million), which also covers 5x as many input tokens.
- Kept a dense 70B worked example but switched to Llama 3.3 70B (verified config identical to 3.1: 80 layers, 8 KV heads, head_dim 128), so all KV and memory arithmetic is unchanged and verified: 327,680 B/token BF16, 163,840 B FP8; 1.2M FP8 KV tokens ≈ 300 sequences at 4K; 5.2 ms + 6.4 ms decode floor; 23k prefill tok/s; 1.4 s stall for a 32K prompt.
- Replaced Mixtral with current MoE examples with verified counts: DeepSeek-V4-Pro (1.6T/49B active), DeepSeek-V4-Flash (284B/13B), Kimi K2 (~1T/32B), gpt-oss-120b (117B/5.1B), Qwen3-235B-A22B.
- Added a B200 TP=2 version of the arithmetic (180 GB, 8 TB/s, 4.5 PFLOPS dense FP8 per GPU derived from DGX B200 specs) and GB200 NVL72 (72-GPU NVLink domain, 13.4 TB HBM3e) for large MoE.
- Added FP4 (NVFP4/MXFP4) row and paragraph; noted gpt-oss-120b MXFP4 and DeepSeek-V4 FP4 experts.
- Added NVIDIA Dynamo and llm-d as disaggregation stacks (verified from their READMEs).
- Added a second diagram for disaggregated serving.
- Moved "How to measure" into the standard section and expanded it; restructured into the AUTHORING sections; no "Thinking at scale" section because the original has no org/ownership content beyond build-vs-buy, which is in Tradeoffs.

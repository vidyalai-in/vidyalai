## Issues found
- "About 700 × 40 tok/s ≈ 28k appends/s, coalesced to ~3-5k writes/s" multiplies new streams per second by tokens per second per stream, which is dimensionally wrong. The correct basis is concurrent streams: 700/s × 12 s ≈ 8,400 concurrent (Little's law), × 40 tok/s ≈ 336k tok/s. Coalescing to 50 ms flushes gives ~168k appends/s; a 20 ms flush is shorter than the 25 ms token gap so it stays near 336k/s. The original understated the write rate by roughly 6-12x even before coalescing claims (and ~50x for the "3-5k writes/s").
- The original's "3-5k" figure is only plausible as pipelined round trips per second (e.g. 200 workers flushing every 25-50 ms = 4-8k), not as entries. Clarified.
- SSE frames were written inline with literal `\\n` escapes; unreadable.
- "Auth with EventSource" pitfall had broken bold in the doc export and did not state a fix.
- 32K zombie KV: 32,768 × 327,680 B = 10.7 GB ("about 10 GB" was fine; made exact).
- "Zombie generations can waste 5-15% of decode capacity" has no source; reframed as a plausible illustrative range.
- Anthropic docs URL (docs.anthropic.com) now 301-redirects to platform.claude.com; OpenAI's platform.openai.com/docs/api-reference/streaming is bot-blocked (403) and the docs now live on developers.openai.com.
- Tables: fake bold header row, `\~` escapes; horizontal rules.

## Changes made
- Rewrote the capacity section with explicit Little's-law arithmetic (8,400 streams, 336k tok/s, 168k-336k appends/s), plus per-worker pipelining (4-8k round trips/s), sharding by message_id, and a memory estimate (about 9 GB at a 10-minute TTL, about 1 GB with a 60 s post-completion TTL; 100 B/entry assumption stated).
- Linked the 12 s stream duration to 400 tokens at 40 tok/s plus TTFT, and the 700/s arrival rate to the chat-at-scale post's peak.
- Put headers, delta frames, heartbeat and error frames in fenced code blocks.
- Verified and stated: ALB default idle timeout 60 s and ALB ignoring HTTP/2 PING frames for idle timeout; nginx `proxy_read_timeout` 60 s default, `proxy_buffering on` default, `X-Accel-Buffering` semantics.
- Added a concrete fix for EventSource auth (fetch with Authorization header, or short-lived single-use stream token).
- Added note that EventSource sends Last-Event-ID automatically while fetch clients must send it.
- Moved deploy/draining and policy ownership into "Thinking at scale".
- Added a sequence diagram of POST, stream, disconnect, reconnect with Last-Event-ID and replay.

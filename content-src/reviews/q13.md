## Issues found
- "use the structured-outputs mode where it's available": outdated. Claude API structured outputs are GA: JSON outputs via `output_config.format` and strict tool use via `strict: true`; the old `output_format` parameter is deprecated and needs the `structured-outputs-2025-11-13` beta header.
- "research has found format restrictions degrade reasoning" presented Tam et al. 2024 as settled; the .txt team's rebuttal ("Say What You Mean") disputes the methodology.
- "Put a reasoning field first" is unsafe advice on Claude structured outputs: Anthropic's docs warn a property asking for step-by-step reasoning may trigger a `reasoning_extraction` refusal.
- OpenAI description only covered `response_format` (Chat Completions); the Responses API uses `text.format`.
- "95-99.5%" prompt-only parse rate and "1-5% failures at scale" have no source.
- Field-order advice did not account for Anthropic emitting required properties before optional ones.
- docs.anthropic.com and platform.openai.com links redirect (301).

## Changes made
- Rewrote the hosted-API section: OpenAI (`text.format` / `response_format`, `strict: true`, required + `additionalProperties: false`, first-request latency, launch eval 100% vs <40%); Anthropic (GA JSON outputs and strict tool use, deprecated `output_format` + beta header, unsupported schema features, 24 h grammar cache, `refusal` and `max_tokens` stop reasons, non-strict `tool_choice` gives no guarantee).
- Presented both sides of the reasoning-degradation debate with numbers from each source (Tam et al.: decline on reasoning, classification unaffected/improved; Kurt/.txt: matched-prompt re-run on Llama-3-8B-Instruct, e.g. GSM8K 0.78 vs 0.77).
- Reasoning advice now prefers the model's native thinking channel, then a short rationale field, then two-step.
- Labeled 95-99.5% and ~5% overhead as illustrative; softened "1-5%" in the table.
- Added worked JSON Schema with `status` enum and nullable fields, and a Pydantic semantic-check sketch reusing the original's "quantity must be ≤ stock (12)" example.
- Truncation section now lists the stop signal per API.
- Added `## Thinking at scale` (schema registry, grammar cache warm-up, provider portability, central validators).
- Diagram: `diagrams/q13-json-pipeline.mmd` (constrained decoding → stop reason → parse/validate → semantic check → bounded repair or fallback).
